# 实现 Review 和公开发布整理

本轮保留已实现的形成、证据、更新链、混合检索语义，整理成独立 Cargo workspace。embedding 与重排模型改由外部 llama-server（Q8_0 GGUF）提供，服务通过 HTTP 调用，不再内置推理框架。评测仍停留在已完成的 conv-26；没有重新跑付费答题，也没有启动剩余九段。

## 已修复问题

| 发现 | 影响 | 修改及验证 |
|---|---|---|
| 配置未知字段和零值缺少统一检查 | 拼写错误被忽略；零批次、零并发及非法评分参数可能使任务失败或停滞 | 启动前校验，拒绝未知字段与非对象配置；纯规则测试及实际 CLI 回归覆盖 |
| embedding 数组把非字符串静默转换成空文本 | 返回错误语义的向量；大型数组也可能耗尽推理资源 | 逐项检查类型，非空数组最多 128 项；HTTP 回归覆盖数字、混合数组、空数组及超限 |
| reindex 无参数仍报告调度成功，HTTP 错误不影响退出状态 | 调用者误认为索引已重建 | 要求显式选择索引种类；HTTP 失败返回非零退出码 |
| 可绑定非本机地址，管理与租户接口无认证 | 对外部署时数据和付费作业可能被任意访问 | 仅允许 loopback IP；文档明确远程访问需认证网关，租户头不代表权限 |
| 旧底座与服务、脚本、缓存混放，旧 CI 不对应当前服务 | 难以判断入口与依赖，容易将本机数据或权重发布 | 导出独立项目、分层模块、三个 crate、固定依赖、统一构建测试入口与新 CI |
| 评测快照缺少准确的来源许可 | 公开发布无法区分代码与数据条款 | 四个必要参考文件逐字核对固定上游提交，保留 Apache-2.0；LoCoMo 单独列 CC BY-NC，数据只在本地下载 |

## 文件和发布管理

旧工程、原始评测证据与模型仍保留在本地。公开仓库以新历史发布独立源码，不继承临时提交、私有 handoff 包或机器配置。

Rust 模块按 API、形成、检索、运行时、存储、领域类型和诊断划分。纯日期及更新规则提为 `memory-rules`，检索评分提为 `retrieval/scoring.rs`，避免重复代码和主服务测试依赖膨胀。旧代码索引服务与无关 transformer vendor fork 不纳入此项目。

包名、类型、环境变量、HTTP 头、脚本及文档统一采用中性命名。公开接口为 `X-Memory-*` 和 `MEMORY_*`，二进制为 `agent-memoryd`。仓库没有旧命名兼容别名；已有客户端应按新 API 文档配置。

模型权重全部排除，包括 BGE 的 GGUF 文件。下载和启动 llama-server 的脚本可以公开。数据集、缓存、数据库、原始 trace、账单和本机绝对路径不提交。发布检查验证实际 Git 暂存区，而不仅依赖 `.gitignore`。

## 保留的限制

- 单用户本机服务，尚无远程认证、多用户权限或生产部署承诺。
- embedding 与重排模型使用 Q8_0 量化，与 FP32 相比有小幅分数偏差；llama-server 的 GPU 统一内存峰值没有可靠进程级测量。
- P4/P5 的自动整理只在保守规则下运行；不同正文合并仍是提案，不自动应用。
- 中文 prompt 对 Agent 角色的假设、历史评测的 80 字符出处上限（当前已按用户要求改为 1024 字符）及历史重放新近度仍影响效果，未为成绩调参。
- `wrong` 反馈后的 candidate 确认流程仍需独立管理接口；当前纠正接口只接受 current。
- 预算是软限制，受并发、重试、节假日价格和进程重启影响；费用与效果必须分别报告。

CI 使用模拟模型检查服务接口，不运行付费评测或上传任何权重。
