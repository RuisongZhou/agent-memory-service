## 联合形成作业
一次处理事实、经验和会话摘要。本批事实只从<本批对话>抽取；<任务上下文>只用于理解跨批次任务，不重复抽取其中的事实。
经验可以引用<本批对话>及<任务上下文>中的原文轮编号，但必须至少引用<本次处理轮>中的一轮。没有明确结果的任务写 unknown，不生成经验。
<当前会话摘要>的 pendingTasks 是尚未结束的任务。分析这些任务时沿用其 task 名称，保留已有支撑轮，并加入新的支撑轮；只有本批明确验证了结果才结束该任务。不要遗漏或擅自结束尚未完成的任务。
更新摘要时保留仍成立的决定，openIssues 给出当前仍未解决的事项，移除本批已明确解决的事项。

## 输出结构：formation-object-v2
只输出一个符合所提供 JSON Schema 的 JSON 对象。facts、analysis、experiences、summary 四个字段均必填。禁止位置行数组和顶层数组，无内容的列表输出 []，summary 始终为对象。
facts：对象数组，每项含 text、scope（global/project）、entities（字符串数组）、effectiveAt（YYYY-MM-DD）、origin（explicit/user/assistant）、source（含 turnId 和 span 的对象）、relations（含 memoryId 和 relation 的对象数组）、reason（字符串或 null）。
source.span 必须逐字复制，每段最多 1024 个 Unicode 字符，含空格和标点。旧事实用 M1 等，本批事实按顺序用 F1 等；关系为 same、updates、conflicts、related，不能引用自身。
analysis：对象数组，每项含 task、result（success/failure/partial/unknown）、turnIds（字符串数组），未验证结果填 unknown。
experiences：对象数组，每项含 situation、approach、result（以 success/failure/partial 开头）、lesson、scope（global/project）、turnIds（字符串数组）、relations（含 memoryId 和 relation 的对象数组）。仅用 E1 等引用旧经验，关系仅 same/related；每个有明确结果的任务最多一条，每批最多三条。
summary：含 goal、outcome、decisions（字符串数组）、openIssues（字符串数组）的对象。
用中文写记忆，专有名词和标识符保留原文。只输出 JSON，不附 Markdown 或解释。
仅引用本批或任务上下文提供的真实对话轮编号。M/F/E 是记忆或事实编号，不能作为对话轮编号。不要重复支撑轮编号，遵守 Schema 中的轮编号枚举和列表长度限制。
