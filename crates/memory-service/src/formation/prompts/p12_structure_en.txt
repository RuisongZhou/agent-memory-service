## Combined formation job
Process facts, experiences and the session summary in one response. Extract facts only from <current batch>. <task context> supports cross-batch task understanding; do not re-extract its facts.
Experiences may cite source turn IDs from <current batch> and <task context>, but must cite at least one <processed turns> ID. Unknown/unverified outcomes produce analysis with unknown and no experience.
The pendingTasks in <current session summary> are unfinished tasks. Reuse each task's exact task name when analyzing it, keep its supporting turn IDs, and add new supporting turns. Close it only with a verified result in this batch. Do not omit or prematurely close an unfinished task.
Summary decisions retain still-valid decisions; openIssues lists currently unresolved matters and removes those explicitly resolved in this batch.

## Output structure: formation-object-v2
Return exactly one JSON object matching the supplied JSON Schema. All four keys are required: facts, analysis, experiences, summary. Never return positional rows or a top-level array. Use empty arrays for sections with no items; summary is always an object.
facts: objects with text, scope (global/project), entities (string array), effectiveAt (YYYY-MM-DD), origin (explicit/user/assistant), source (object with turnId and span), relations (objects with memoryId and relation), reason (string or null).
Copy each source.span verbatim, at most 1024 Unicode characters including spaces and punctuation. Facts use M1 etc. for old memories or F1 etc. for current facts in order. Relation types: same, updates, conflicts, related. Never reference the same fact.
analysis: objects with task, result (success/failure/partial/unknown), turnIds (string array). Analyze currently processed tasks and retained unfinished tasks. Unconfirmed outcomes are unknown.
experiences: objects with situation, approach, result (starting with success/failure/partial), lesson, scope (global/project), turnIds (string array), relations (objects with memoryId and relation). Only E1 etc. for old experiences and same/related relation types. At most one experience per task with a verified outcome and at most 3 per batch.
summary: object with goal, outcome, decisions (string array), openIssues (string array).
Write memories in English. Preserve original names and identifiers. Output JSON only; no Markdown or explanations.
Only cite actual dialogue turn IDs supplied in the current batch or task context. M/F/E labels identify memories or facts, never dialogue turns. Do not repeat source turn IDs. Follow the source ID enums and list limits in the supplied schema.
